# Decisions

Each decision, why, and the date. The newest is last. Where something was ambiguous, the
simplest option that keeps quality won.

| # | Date | Decision | Why |
|---|---|---|---|
| 1 | 2026-11-19 | Keep the name **DryRun**. | The only product with the name in this space is a small student algorithm-quiz site (dryrun1002.vercel.app) that doesn't run your own code. Python Tutor is the established tool for tracing code; it isn't called DryRun. |
| 2 | 2026-11-19 | Pyodide **314.0.7** (Python 3.14), installed from npm and copied into `web/public/pyodide/` at build time, served from our own origin. | 314.0.8 was published 2026-11-13, under 14 days old; 314.0.7 (2026-09-14) is the newest that passes the rule. The npm package carries the core runtime and the standard library zip, which is all the tracer needs (`collections`, `heapq`, `ast`, `json`). Pinning through npm puts Pyodide under the same lockfile, age check and audit as everything else. |
| 3 | 2026-11-19 | `scripts/check-deps.mjs` is gridrace's, with one addition: a PyPI reader for `requirements.txt` (exact `==` pins, transitive packages listed). The Rust toolchain check runs only when `rust-toolchain.toml` exists. | Reuse what is tested. pytest is the only Python dependency, and it is test-only. |
| 4 | 2026-11-19 | CI tests the tracer on CPython **3.14**, the Python inside Pyodide 314. | The tracer runs on both; matching the minor version keeps `sys.settrace` and AST behaviour the same. A Node + Pyodide smoke test covers the real runtime. |
| 5 | 2026-11-19 | A step records the state **before** its line runs (Python's `line` event fires before execution), plus `call`, `return` and `exception` events. | It's the semantics of `sys.settrace` and of every debugger: "the arrow is on the line about to run". The UI says so. |
| 6 | 2026-11-19 | The heap is sent as deltas: an object is re-sent only when its serialised form changes; locals the same per frame. | A 5,000-step trace of a 100-element array would otherwise repeat the array 5,000 times. Identity comes from the per-run id map, which keeps every object alive so CPython never reuses an `id()`. |
| 7 | 2026-11-19 | Reads, writes, pointers and structure operations come from a static pass over each line's AST, evaluated against the frame's locals **before** the line runs, with a tiny side-effect-free evaluator (names, int constants, `+ - * // %`, tuples, subscripts of builtin containers, instance attributes found in `__dict__`). | Opcode tracing would be exact but several times slower in Pyodide. The static pass never runs user code (no `__getitem__`, `__repr__` or property is called; a defaultdict is read with `dict.__contains__` so it doesn't insert). Limit: an operation on a line inside a short-circuited expression is counted even if it didn't run. |
| 8 | 2026-11-19 | Limits: 5,000 steps, 200 nested calls, 5,000 calls, 200 heap objects and 120 items per container per snapshot, 200 characters per string, 6 MB of trace, 8 s inside the tracer, and a 15 s watchdog that terminates the worker. | Big enough for every textbook-size input, small enough that the trace (and the page) stays responsive on a phone. Each cap is reported with the step and line where it hit. |
| 9 | 2026-11-19 | In "call a function" mode the module runs with `__name__ = "dryrun"`. | A typical solution file reads stdin under `if __name__ == "__main__":`; call mode should skip that block. |
| 10 | 2026-11-19 | Views are chosen once per trace from what the program *did* with each variable (operations, index pointers, attribute reads), not per step from shapes. | A view that changes kind between steps is unreadable. Behaviour beats shape: an islands map and an adjacency matrix are both rectangular int lists, but only one is pushed to a queue of neighbours. Comment hints override. |
| 11 | 2026-11-19 | Tree visit order = the order each node's payload (`val`, `value`, `data`, `key`) was first read. | For a recursive in-order walk that is in-order, for BFS it is level order; the order of calls would be pre-order for every walk. |
| 12 | 2026-11-19 | A memo hit = a call that made no calls and read a dict its own function writes elsewhere. | A base case also makes no calls but reads no memo. `@functools.cache` hits never enter the function, so they can't be drawn; the README says so. |
| 13 | 2026-11-19 | Plain CSS with custom properties, no Tailwind. | Two pages, one design system; fewer dependencies under the 14-day rule. |
| 14 | 2026-11-19 | Two pages: a static landing page at `/` (no React, no Pyodide) and the app at `/app`. | The landing page needs real HTML for crawlers and Performance >= 95; the app starts loading Python as soon as it opens. |
| 15 | 2026-11-19 | Pyodide is cached by the service worker on first load (runtime cache, versioned path), not precached at install. | Precaching 12 MB on a visit to the landing page would cost visitors who never open the app. |
| 16 | 2026-11-19 | Download progress counts bytes of the two big files against their uncompressed size, fixed at build time. | A compressed response's `content-length` undercounts what the stream delivers. |
| 17 | 2026-11-19 | Icons and the Open Graph image are rendered on CI from HTML (`web/scripts/assets.mjs`) and not committed. | The laptop doesn't run Chromium; the images stay reproducible from the app's own faces and palette. |
| 18 | 2026-11-19 | The deploy job deploys the exact `dist` the e2e suite tested (artifact), and a live-site job runs a subset of e2e, the analytics-script check and Lighthouse after it. | Building twice could ship something untested. |
| 19 | 2026-11-19 | PRODUCT.md was written from the brief without Impeccable's interview. | The brief asked for no stops; assumptions are marked in the file. Hallmark's Floor and sweep apply; its theme deal was skipped because the brief pins the look. |
